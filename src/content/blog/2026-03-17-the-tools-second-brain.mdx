## the stack at a glance

before we go deep, here's the full picture:

```
YOUR SECOND BRAIN
─────────────────────────────────────────────
MEMORY LAYER      →  notion or obsidian
REASONING LAYER   →  claude (anthropic)
BUILDER LAYER     →  claude code
RUNTIME LAYER     →  openclaw
MEMORY FILES      →  markdown (.md files)
─────────────────────────────────────────────
```

each layer has one job. together they create something that thinks with you — not just stores things for you.

## 1. the memory layer: notion vs. obsidian

these are the two real options. pick one. don't use both.

### [notion](https://notion.so)

**what it does:** structured, relational knowledge storage. your second brain's long-term memory.

notion's power is in databases. you can link a person to a project, a project to a decision, a decision to an outcome. it's not a notes app — it's a relational map of your world that an ai agent can query.

**what it costs:** free for individuals. notion ai adds $10/mo. teams from $15/user/mo.

> **the honest take:** most people set up notion wrong. they treat it like dropbox for documents. the real power is in linked databases and formulas. if you're not willing to spend a week setting it up properly, it becomes a graveyard.

**alternatives:**
- **[anytype](https://anytype.io)** — local-first, closer to notion's structure. early but promising.
- **[coda](https://coda.io)** — stronger automation than notion. better if you're building internal tools.
- **[airtable](https://airtable.com)** — pure database, weaker on freeform notes.

---

### [obsidian](https://obsidian.md)

**what it does:** markdown-based personal knowledge base. everything lives as plain text files on your machine.

this is what you use when you want your second brain to be truly yours. no servers, no subscriptions (core is free), no risk of a company going under taking your data with it. your files are just files — readable forever, portable anywhere.

**what it costs:** free. [obsidian sync](https://obsidian.md/sync) is $10/mo if you want cross-device.

the plugin ecosystem is where it gets serious:
- **dataview** — turns your notes into queryable databases
- **templater** — automates note creation
- **graph view** — visualizes connections between ideas

> **the honest take:** steeper setup than notion, but the payoff is full ownership. and here's the real advantage for ai second brains — when your notes are plain markdown files, an ai agent can read and write them directly from the filesystem. no api needed.

**the framework to pair with it:** [para by tiago forte](https://fortelabs.com/blog/para/) — projects, areas, resources, archives. gives obsidian the organizational structure it lacks natively.

---

### notion vs. obsidian: the real comparison

| | notion | obsidian |
|---|---|---|
| **data ownership** | cloud (notion's servers) | local (your machine) |
| **ai agent access** | via api | direct filesystem |
| **setup time** | 1-2 weeks | 2-4 weeks |
| **relational data** | native | via plugins |
| **cost** | free → $15+/mo | free |
| **best for** | teams, crm, structured data | individuals, writers, researchers |

**verdict:** use notion for relational power. use obsidian for ownership and simplicity. don't use both.

## 2. the reasoning layer: claude

**[claude by anthropic](https://claude.ai)** is the intelligence on top of your knowledge base. reads, reasons, writes, plans, executes.

why claude specifically, and not chatgpt or gemini?

for second brain work, the winner is the model that actually follows your instructions — not the fastest or cheapest one. when you give claude your memory files, your preferences, your open loops — it holds the context and follows the rules you've set.

**what it costs:** claude.ai pro is $20/mo. api access is roughly $3–15 per million tokens depending on model tier.

> **the honest take:** best model for careful, high-stakes reasoning right now. not the cheapest. not the fastest. but if you're building something that's supposed to actually *think* — not just generate — it's worth the cost.

**alternatives:**

| model | best for | weakness |
|---|---|---|
| **[gpt-4o (openai)](https://openai.com)** | speed, volume, integrations | weaker instruction-following |
| **[gemini 1.5 pro (google)](https://deepmind.google/gemini)** | 1M token context, long docs | weaker nuanced reasoning |
| **[local models via ollama](https://ollama.com)** | free, private, offline | quality gap vs. frontier models |

## 3. the builder layer: claude code

**[claude code](https://claude.ai/code)** is an ai coding agent that operates directly in your filesystem. reads files, writes code, runs terminal commands, builds and deploys.

most people think about second brains as static systems — notes and databases. a real second brain grows and adapts. claude code is what lets you build the infrastructure without being a full-time developer.

you describe what you want. it reads your existing code, figures out the approach, and builds it. it makes mistakes. you correct them. it's closer to working with a junior developer than a code generator.

**what it costs:** included in claude.ai pro ($20/mo) or via api at usage rates.

> **the honest take:** the most underutilized tool in the stack. people use claude for writing and thinking. very few use it to actually *build* their second brain. if you're willing to give it clear instructions, you can build things you never thought you could — dashboards, automations, custom tools.

**alternatives:**
- **[cursor](https://cursor.com)** — ai-native code editor. better for professional developers. more control, more complexity.
- **[github copilot](https://github.com/features/copilot)** — solid autocomplete. assists rather than executes.
- **[codex (openai)](https://openai.com/blog/openai-codex)** — strong for code generation within git repos.

## 4. the runtime layer: openclaw

this is the piece most people are missing.

you can have notion. you can have claude. but without something connecting them, you're still doing all the work manually — copying information between tools, prompting claude fresh every morning, losing context between sessions.

**[openclaw](https://openclaw.ai)** runs as a background process on your machine. it maintains a persistent agent session, connects to your knowledge base, executes tools, and keeps the agent active 24/7. it's what turns a chat interface into an actual second brain.

what it enables:
- receive messages via telegram (or slack, signal, discord)
- read and write to your filesystem automatically
- call external apis on your behalf
- run scheduled automations (crons) — morning briefing, memory consolidation, nightly review
- maintain context between sessions without losing the thread

**what it costs:** open source. free to self-host. requires a machine to run on — a laptop, a [beelink mini pc](https://www.bee-link.com/), a vps, or a raspberry pi.

> **the honest take:** highest-leverage tool in the stack for people serious about a real agent. also the most technical. if you're not comfortable running software on a local machine, start with the other tools first. but if you want a second brain that *does things* without you prompting it every time — this is the layer you need.

**alternatives:**
- **[n8n](https://n8n.io)** — visual workflow automation. lower ceiling but lower technical bar.
- **[make](https://make.com)** — hosted, easier setup than n8n.
- **[zapier](https://zapier.com)** — most accessible. least powerful for ai-native workflows.

## 5. the memory structure: markdown files

this is the part nobody talks about.

the tool stack is only as good as what you feed it. a second brain without structured memory is just a faster way to forget things.

here's the file structure that runs this system:

```
C:\second-brain\
├── MEMORY.md          ← long-term distilled context (updated nightly)
├── SOUL.md            ← who your agent is — voice, tone, principles
├── SESSION-STATE.md   ← hot working memory — open loops, current priorities
├── memory\
│   ├── 2026-03-17.md  ← today's log (timestamped bullets)
│   ├── 2026-03-16.md  ← yesterday
│   └── people\
│       ├── john-smith.md
│       ├── sarah-jones.md
│       └── [one file per person]
└── memory\projects\
    └── [one file per project]
```

when the agent starts a session, it reads these files. when it ends, it writes to them. the memory persists between restarts because it's in files — not in the model's context window.

> **the principle:** your second brain is only as smart as what you've written down. the tools execute. the memory is the content. invest in both.

## how it all connects

```

 │
 ▼

 │  reads your message, routes it to claude
```

nothing in this stack is magic. it's just the right tools, connected in the right order, with memory that persists.

## what to take away

- **notion or obsidian** — pick one, go deep. notion for relational power, obsidian for ownership. don't split between them.
- **claude** for the reasoning layer — instruction-following matters more than speed for second brain work.
- **claude code** to build your own infrastructure — more accessible than it looks.
- **openclaw** if you want an agent that does things without you asking every time.
- **structured markdown files** as the memory layer — your agent is only as good as what you've written down.
- before adopting any tool, ask: does it have an api? can an agent read and write to it? if not, it's a dead end.

the second brain isn't a single tool. it's a stack. and the stack only works when the pieces connect.
